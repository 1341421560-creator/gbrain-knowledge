<a id="core-conclusions"></a>
## 1. 核心结论

- `client2.conf` 只能提供 VPN 连接和流量转发能力，不能直接登录服务器。
- 服务器浏览器访问网站通常不会暴露本机 IP，但登录账号、同步浏览器或复用 Cookie 会带来关联风险。
- 通过 VPN 不能自动向对方电脑发送文件；除非对方电脑主动开放接收服务。

<a id="faq"></a>
## 3. 独立 FAQ

<a id="section-client2-能不能登录我的服务器"></a>
### 1. client2 能不能登录我的服务器？

**直接回答：** 不能。`client2.conf` 是 AmneziaWG VPN 配置，不是 SSH 密钥，也不是 Linux 用户密码。

client2 能做的是连接 VPN 并让网络流量通过服务器转发。它不能直接 SSH 登录服务器、拿到 root 权限、打开 VNC 或访问服务器文件系统。

<a id="section-client2-能不能访问服务器本机服务"></a>
### 2. client2 能不能访问服务器本机服务？

**直接回答：** 默认进入 VPN 网段后，理论上可能访问服务器 VPN 地址上的服务；如需限制，可以用防火墙禁止 `10.66.66.3` 访问服务器本机服务，只允许 NAT 出网。

历史上曾添加过 UFW 拒绝规则，后来按用户要求恢复原权限。

<a id="section-能不能查看-client2-打开了哪些应用"></a>
### 3. 能不能查看 client2 打开了哪些应用？

**直接回答：** 通常不能完整看到对方打开了哪些应用。

服务器可以看到 client2 是否连接、流量总量、目标 IP、端口和部分 DNS 查询。服务器通常看不到对方电脑具体哪个应用发起连接，也看不到 HTTPS 内容、账号密码和页面路径。

可临时查看流量：

```bash
tcpdump -ni awg0 host 10.66.66.3
```

涉及他人网络行为监控时，应先告知并取得同意。

<a id="section-能不能通过-vpn-端口给对方电脑发送东西"></a>
### 4. 能不能通过 VPN 端口给对方电脑发送东西？

**直接回答：** 一般不能。VPN 隧道不是远程控制或文件传输通道。

除非对方电脑主动开放 SMB、SSH、RDP、HTTP 或其他接收服务，否则你不能仅凭 VPN 配置向对方电脑发送文件。传文件更适合用网盘、聊天软件、SFTP 或让对方主动下载。

<a id="section-在服务器浏览器中打开网页会暴露本机-ip-吗"></a>
### 5. 在服务器浏览器中打开网页会暴露本机 IP 吗？

**直接回答：** 正常不会。网站接触到的是服务器浏览器发出的请求，通常看到服务器 IP `187.127.123.84`。

风险来自登录账号、同步浏览器、复用本机 Cookie、上传包含本机信息的文件或在服务器内配置本机代理。

<a id="section-服务器代理是本机代理吗"></a>
### 6. 服务器代理是本机代理吗？

**直接回答：** 默认不是。服务器有自己的公网网络，除非主动设置 SSH 动态代理、本机代理转发、浏览器代理或环境变量代理。

服务器访问外网通常走服务器自己的出口。

<a id="section-codex-对话窗口用的是服务器网络还是本机网络"></a>
### 7. Codex 对话窗口用的是服务器网络还是本机网络？

**直接回答：** Codex 本身是本机 agent 环境，不是在服务器里运行。通过 SSH 发出的命令可以在服务器执行，但 Codex 对话窗口不是服务器浏览器。

因此 Amazon 抓取的约束是：Codex 本机可以编辑和上传脚本，但 Amazon 请求必须由服务器侧脚本发出。

<a id="section-amneziawg-官方客户端和-clash-verge-能不能同时开"></a>
### 8. AmneziaWG 官方客户端和 Clash Verge 能不能同时开？

**直接回答：** 不建议同时开。

两个同时开可能导致路由冲突、DNS 混乱和速度变慢。使用 Clash Verge 分流时，应关闭官方 AmneziaWG；使用官方 AmneziaWG 全局 VPN 时，应关闭 Clash Verge 的 TUN 或相关代理。

<a id="section-cr-普通账户权限高吗"></a>
### 9. cr 普通账户权限高吗？

**直接回答：** 不高。`cr` 是普通账户，当前只有 `cr` 自己的用户组，没有 sudo 权限。

它可以管理 `/home/cr` 下自己的文件，不能直接查看 `/root`，不能安装系统软件，不能改系统配置，不能开放系统防火墙端口，也不能管理其他用户。

<a id="section-为什么-cr-看不到-root-创建的文档"></a>
### 10. 为什么 cr 看不到 root 创建的文档？

**直接回答：** 因为 root 的文件通常在 `/root` 或 root 拥有的目录里，普通账户默认无权查看。

这不是文件丢失，而是 Linux 权限隔离。要查看 root 文件，用 root 登录；要让 `cr` 使用文件，需要 root 复制到 `/home/cr` 并执行 `chown cr:cr`。

<a id="section-私钥复制到新路径后-内容一样-效果也一样吗"></a>
### 11. 私钥复制到新路径后，内容一样，效果也一样吗？

**直接回答：** 对服务器认证来说一样；对本机 SSH 客户端来说，还取决于新文件路径的 Windows ACL。

两个私钥如果公钥指纹一样，就是同一把密钥。历史对比过当前新旧私钥，指纹相同：`SHA256:dN3jS9akeKF8Rqd6tkPDd6Z/FYTovrHMAZpFEC8Nd0o`。但复制后的文件会继承新目录权限，如果权限太开放，OpenSSH 会忽略它。

<a id="section-只有-ai454-读取权限-是什么意思"></a>
### 12. “只有 AI454 读取权限”是什么意思？

**直接回答：** 这是 Windows 本机私钥文件权限，不是服务器权限。

意思是本机 `codex_ed25519` 文件只有 Windows 用户 `AI454` 可以读取。服务器里的 `/home/cr/.ssh/authorized_keys` 没有因此改变，服务器只保存公钥，不保存私钥。

<a id="section-要不要新建服务器端口"></a>
### 13. 要不要新建服务器端口？

**直接回答：** 只登录服务器、管理文件和使用现有 VNC/VPN 时，不需要新建端口。

端口只有在服务器要对外提供新服务时才需要，例如网站 `80/443`、API `3000/5000/8000`、VNC 隧道本地映射 `5901/5902`、AmneziaWG `51821/UDP`。端口不是账户权限，`cr` 没有 sudo 时通常不能开放系统防火墙端口。

<a id="section-start-vnc-tunnel-bat-是什么-要用-cr-就改成-5902-吗"></a>
### 14. start_vnc_tunnel.bat 是什么？要用 cr 就改成 5902 吗？

**直接回答：** `start_vnc_tunnel.bat` 是 root VNC 的 SSH 隧道脚本，本地 `5901` 转服务器 `127.0.0.1:5901`，并用 root 建立 SSH 连接。

用 `cr` 连接时应使用 `start_vnc_tunnel_cr.bat`，它用 `cr@187.127.123.84` 并转发 `5902`。不要写成 `5092`。
