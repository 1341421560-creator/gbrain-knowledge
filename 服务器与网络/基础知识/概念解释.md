<a id="core-conclusions"></a>
## 1. 核心结论

- 服务器有自己的网络出口；服务器浏览器访问网站时，网站通常看到服务器 IP，而不是本机 IP。
- SSH、VNC 和 VPN 是不同层面的工具：SSH 管理服务器，VNC 远程控制桌面，AmneziaWG 转发本机网络流量。
- Cookie、浏览器指纹和 WebRTC 是不同维度的识别方式；VPN 只能改变网络出口，不能自动清除浏览器身份痕迹。

## 2. 适用范围

- **适用对象：** 对 Linux VPS、远程桌面、VPN 分流和 Amazon 抓取隔离概念不确定时。

<a id="main-concepts"></a>
## 3. 核心概念

<a id="section-服务器-ip-地址和域名"></a>
### 服务器、IP 地址和域名

服务器是远程运行系统和程序的机器。当前服务器公网 IPv4 是 `187.127.123.84`，网站从服务器侧收到请求时通常看到这个 IP。

IP 地址是网络上的数字地址，域名是给 IP 起的可读名字。域名需要通过 DNS 解析到 IP，浏览器再连接对应服务器。

<a id="section-ssh"></a>
### SSH

SSH 是加密远程登录协议，用于执行命令、上传脚本、管理服务。`ssh root@187.127.123.84` 表示以 root 用户连接该服务器。

SSH 密钥只用于服务器登录，不等于 VPN 配置。别人拿到 AmneziaWG 的 `client2.conf`，不能因此获得 SSH 登录能力。

<a id="section-vnc"></a>
### VNC

VNC 是远程桌面画面协议。当前服务器上 root 和 cr 各有独立 VNC 会话，分别通过 SSH 隧道映射到本机 `127.0.0.1::5901` 和 `127.0.0.1::5902`。

VNC 只是远程控制服务器桌面，不会让本机自动通过 SSH 隧道访问外国网络。

<a id="section-vpn-与-amneziawg"></a>
### VPN 与 AmneziaWG

VPN 是把网络流量通过另一台服务器转发出去的隧道。AmneziaWG 是带混淆参数的 WireGuard 改造版本，包含 `Jc/Jmin/Jmax/S1-S4/H1-H4` 等普通 WireGuard 不支持的字段。

当前 AmneziaWG 服务运行在 `awg0`，端口 `51821/UDP`。

<a id="section-cookie"></a>
### Cookie

Cookie 是网站保存到浏览器的小数据，用于记住登录状态、地区、语言、购物车和风控标记。无 Cookie 状态不是“服务器不能有 Cookie”，而是“不复用本机已有 Cookie”。

Amazon 抓取工程允许服务器自己产生匿名 Cookie，但不允许复制本机 Cookie 或登录 Amazon 账号。

<a id="section-浏览器指纹"></a>
### 浏览器指纹

浏览器指纹是由 User-Agent、屏幕尺寸、字体、WebGL、Canvas、时区、语言、插件、TLS/HTTP2 特征等信息组合出来的识别特征。

VPN 改变的是网络出口，不会自动改变全部浏览器指纹。

<a id="section-webrtc-泄漏"></a>
### WebRTC 泄漏

WebRTC 是浏览器实时通信能力，可能通过 UDP 探测暴露额外 IP 信息。即使开了 VPN，WebRTC 也可能显示本机局域网 IP、IPv6 或非代理 UDP 路径。

浏览器可通过禁用非代理 UDP 或关闭 WebRTC 降低泄漏风险。

<a id="section-mtu"></a>
### MTU

MTU 是每个网络包一次能装多大的限制。它不是速度开关。MTU 太小会降低效率，MTU 太大可能导致丢包、网页卡住或能连但没网。

当前经验值：

- `1280`：更稳。
- `1380`：速度与稳定折中。
- `1420`：理论效率高，但跨境线路不一定稳定。

<a id="section-swap"></a>
### swap

swap 是 Linux 把磁盘空间当作临时内存使用。它能降低内存不足导致程序崩溃的概率，但比真实内存慢，不能真正替代 RAM。

低配 VPS 加 swap 是为了稳定，不是为了提速。

<a id="section-端口"></a>
### 端口

端口是服务器上某个服务的入口号，不是 Linux 账户。IP 是服务器地址，端口是同一台服务器上具体服务的门牌号。

当前常见端口边界：

| 端口 | 用途 |
|---|---|
| `22/tcp` | SSH 登录服务器 |
| `5901/tcp` | root 的 VNC display `:1` |
| `5902/tcp` | cr 的 VNC display `:2` |
| `51821/udp` | AmneziaWG `awg0` |
| `41000/tcp+udp` | Shadowsocks 转发节点 |

“用 cr 登录”和“改 VNC 端口”不是同一件事。用 cr 登录 SSH 隧道时改的是 `root@187.127.123.84` 到 `cr@187.127.123.84`；VNC 端口是否用 `5901` 或 `5902` 取决于要连接哪个 VNC display。

<a id="section-linux-账户权限和家目录隔离"></a>
### Linux 账户权限和家目录隔离

`root` 是系统管理员账户，`cr` 是普通账户。`cr` 当前只有自己的用户组，没有 sudo 权限，默认只能管理 `/home/cr` 下自己的文件。

root 创建或保存的文件通常在 `/root` 或 root 拥有的目录里。`cr` 看不到 `/root` 文件是正常的 Linux 权限隔离，不代表文件丢失。需要查看 root 文件时应使用 root 登录，或由 root 把文件复制到 `cr` 可访问的位置并调整所有者。

<a id="section-ssh-私钥内容和-windows-文件权限"></a>
### SSH 私钥内容和 Windows 文件权限

SSH 私钥内容决定它是不是同一把密钥；Windows 文件权限决定本机 OpenSSH 是否愿意使用它。同一把私钥复制到新路径后，如果继承了 `Users`、`Authenticated Users`、`Everyone` 或 `CodexSandboxUsers` 等可读权限，OpenSSH 会提示 `UNPROTECTED PRIVATE KEY FILE` 并忽略密钥。

当前项目根目录中的 `codex_ed25519` 已收紧为仅当前 Windows 用户可读。服务器端没有因为这次权限修复而改变，服务器仍只保存对应公钥到 `authorized_keys`。
