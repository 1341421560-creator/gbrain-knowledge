<a id="core-conclusions"></a>
## 1. 核心结论

- SSH 用于管理服务器；VNC 通过 SSH 隧道访问服务器桌面；AmneziaWG 用于转发网络流量。
- Clash Verge/Mihomo 分流配置需要使用 Mihomo core，并选择 `AmneziaWG-client2-MY` 作为国外流量节点。
- 测试 VPN 时先测 IP 连通，再测 DNS，最后测出口 IP。
- 在 64.83.43.228 上交互式浏览网页用 RDP，文件互传用 WinSCP/SFTP。两个入口各自独立。
- 64.83.43.228 上的 ChatGPT Linux 桌面版以 `browser` 用户运行。XFCE 使用 IBus 简体拼音，`Ctrl + 空格` 在英文与拼音之间切换。

<a id="scope"></a>
## 2. 适用范围

- **适用对象：** Windows 本机、Hostinger Ubuntu VPS、TigerVNC、64.83.43.228 的 xrdp 桌面、WinSCP/SFTP、AmneziaWG Windows Client、Clash Verge/Mihomo。
- **适用场景：** 登录服务器、连接远程桌面、导入配置、开启分流、测试网络。
- **不适用场景：** 删除配置、重置服务器、重装系统；这些操作需要单独确认。

## 3. 操作指南

<a id="section-ssh-登录服务器"></a>
### SSH 登录服务器

root 登录：

```powershell
ssh -i C:\Users\AI454\OneDrive\Desktop\project\server_knowlege\codex_ed25519 root@187.127.123.84
```

cr 登录：

```powershell
ssh -i C:\Users\AI454\OneDrive\Desktop\project\server_knowlege\codex_ed25519 cr@187.127.123.84
```

首次连接出现 fingerprint 提示时，确认 IP 是 `187.127.123.84` 后输入 `yes`。

<a id="section-打开-root-vnc-桌面"></a>
### 打开 root VNC 桌面

1. 在服务器启动 root VNC：

```bash
cd /root/Desktop/output/vnc_tools
./start-vnc.sh
```

2. 在 Windows 开 SSH 隧道：

```powershell
ssh -i C:\Users\AI454\OneDrive\Desktop\project\server_knowlege\codex_ed25519 -N -L 5901:127.0.0.1:5901 root@187.127.123.84
```

3. TigerVNC Viewer 输入：

```text
127.0.0.1::5901
```

<a id="section-打开-cr-vnc-桌面"></a>
### 打开 cr VNC 桌面

1. 在服务器启动 cr VNC：

```bash
cd /home/cr/vnc_tools
./start-vnc-cr.sh
```

2. 在 Windows 开 SSH 隧道：

```powershell
ssh -i C:\Users\AI454\OneDrive\Desktop\project\server_knowlege\codex_ed25519 -N -L 5902:127.0.0.1:5902 cr@187.127.123.84
```

3. TigerVNC Viewer 输入：

```text
127.0.0.1::5902
```

<a id="section-设置-cr-的-vnc-密码"></a>
### 设置 cr 的 VNC 密码

以 cr 登录后运行：

```bash
vncpasswd
```

出现 view-only password 询问时输入 `n`。

<a id="section-导入-amneziawg-client2"></a>
### 导入 AmneziaWG client2

client2 配置路径：

```text
C:\Users\AI454\Documents\Codex\2026-07-03\zu\output\20260716_amneziawg_client2\client2.conf
```

操作：

1. 安装 AmneziaWG Windows Client。
2. 导入 `client2.conf`。
3. 连接后测试出口 IP。

不要导入普通 WireGuard 客户端，因为普通 WireGuard 不支持 AmneziaWG 混淆参数。

<a id="section-配置-clash-verge-mihomo-分流"></a>
### 配置 Clash Verge/Mihomo 分流

分流配置路径：

```text
C:\Users\AI454\Documents\Codex\2026-07-03\zu\output\20260724_clash_verge_split_config\clash_verge_mihomo_split_client2.yaml
```

操作：

1. Clash Verge 使用 Mihomo core。
2. 导入分流 YAML。
3. 进入代理页面，国外流量选择 `AmneziaWG-client2-MY`。
4. 打开系统代理。
5. 需要非浏览器应用分流时再打开 TUN。
6. 关闭 AmneziaWG 官方客户端，避免双 VPN 冲突。

分流逻辑：

```text
国内网站 -> DIRECT
国外网站 -> AmneziaWG-client2-MY
```

<a id="section-测试-vpn-是否正常"></a>
### 测试 VPN 是否正常

连接后在 Windows PowerShell 运行：

```powershell
ping 1.1.1.1
nslookup google.com 1.1.1.1
curl https://ifconfig.me
```

预期：

- `ping 1.1.1.1` 能通。
- `nslookup google.com 1.1.1.1` 能返回 IP。
- 国外出口检测应显示服务器 IP `187.127.123.84`。

<a id="section-修复-windows-ssh-私钥权限"></a>
### 修复 Windows SSH 私钥权限

如果 SSH 登录时明明指定了私钥，却出现 `UNPROTECTED PRIVATE KEY FILE` 或退回到输入 Linux 密码，通常是私钥文件 ACL 太开放。

在项目目录中修复当前私钥：

```powershell
cd "C:\Users\AI454\OneDrive\Desktop\project\server_knowlege"
$path = ".\codex_ed25519"
$me = "$env:USERDOMAIN\$env:USERNAME"
icacls $path /inheritance:r
icacls $path /remove:g "DESKTOP-5P7UDUM\CodexSandboxUsers" "Users" "Authenticated Users" "Everyone"
icacls $path /grant:r "$($me):(R)"
```

验证：

```powershell
icacls .\codex_ed25519
ssh -i ".\codex_ed25519" cr@187.127.123.84
```

预期登录后：

```text
cr
/home/cr
```

<a id="section-使用-vnc-隧道脚本"></a>
### 使用 VNC 隧道脚本

项目根目录有两个 VNC 隧道脚本：

| 脚本 | SSH 用户 | 本地端口 | 远端端口 | Viewer 地址 |
|---|---|---:|---:|---|
| `start_vnc_tunnel.bat` | `root` | `5901` | `5901` | `127.0.0.1::5901` |
| `start_vnc_tunnel_cr.bat` | `cr` | `5902` | `5902` | `127.0.0.1::5902` |

隧道窗口必须保持打开。关闭窗口后，TigerVNC Viewer 到 `127.0.0.1::5901` 或 `127.0.0.1::5902` 的连接也会断开。

<a id="section-查看-root-创建的文件"></a>
### 查看 root 创建的文件

`cr` 登录后默认在 `/home/cr`，看不到 `/root` 是正常权限隔离。需要查看 root 文件时：

```powershell
ssh -i ".\codex_ed25519" root@187.127.123.84
```

服务器内查看：

```bash
ls -la /root
```

如果要让 `cr` 使用某个 root 文件，由 root 执行复制并改所有者：

```bash
cp /root/file-name /home/cr/
chown cr:cr /home/cr/file-name
```

<a id="chatgpt-linux-desktop-install"></a>
### 在 64.83.43.228 安装 ChatGPT Linux 桌面版

2026-11-06 在 Ubuntu 22.04 LTS、`amd64`、XFCE/xrdp 环境实测安装 OpenAI ChatGPT Linux 桌面预览版 `26.1103.31037`。OpenAI Docs 当时列出的 Ubuntu 支持版本是 24.04 LTS 和 26.04 LTS。22.04 是本案例的实测环境。 [OpenAI Docs 的 Linux 安装与支持说明](https://learn.chatgpt.com/docs/linux/linux-app)

1. 在服务器 Chrome 从官方地址下载 `chatgpt_amd64.deb`，保存在 `/home/browser/downloads/`。下载记录与官方地址一致，文件为 562,447,122 字节。本地计算的 SHA-256 为 `32fed80ad3f8caf666e5860022361e9709d64aa318cfb19f548e8b458d4f6793`。 [官方 Ubuntu x64 下载](https://persistent.oaistatic.com/codex-app-prod/linux/deb/latest/chatgpt_amd64.deb)
2. 安装软件包使用服务器的管理 SSH 会话。`browser` 用户直接运行 `apt install` 时出现 `dpkg lock-frontend Permission denied`，对应的是安装权限。使用本地文件时给 APT 传入 `./chatgpt_amd64.deb` 或绝对路径。
3. 先用 `apt-get -s --no-remove install ./chatgpt_amd64.deb` 预演。本次仅新增 ChatGPT 和 `mesa-vulkan-drivers`，无现有软件升级或移除。依赖版本为 `23.2.1-1ubuntu3.1~22.04.4`，其包已保存在同一下载目录并按 Ubuntu 软件索引的 SHA-256 核对。
4. 这次 APT 使用 `--no-download` 时未获取本地归档，最终用以下两份已核验的本地包完成安装。以后安装不同版本时，先用预演结果重新核对依赖。

```bash
cd /home/browser/downloads
dpkg --install './mesa-vulkan-drivers_23.2.1-1ubuntu3.1~22.04.4_amd64.deb' ./chatgpt_amd64.deb
dpkg-query -W chatgpt mesa-vulkan-drivers
```

5. 以 `browser` 在 XFCE 远程桌面里打开应用菜单中的 **ChatGPT**，或双击 `/home/browser/Desktop/ChatGPT.desktop`。终端入口是 `chatgpt`，系统菜单文件是 `/usr/share/applications/chatgpt.desktop`。实测可见 ChatGPT 主窗口，并观察到内置 `codex` 进程启动。验证覆盖安装与启动。

**启动临时目录。** 第一次手动启动使用了较长的 `TMPDIR`，Chromium 报 `Socket path too long`，报错路径以 `SingletonSocket` 结尾。改用较短且归 `browser` 所有的 `/home/browser/temp/chatgpt` 后，主窗口成功显示。安装和成功启动的日志在服务器 `/opt/remote-browser-20261103/temp/20261106_chatgpt_install/`，文件为 `install.log` 和 `launch-short-temp.log`。

<a id="xfce-ibus-libpinyin"></a>
### 在 XFCE 远程桌面配置 IBus 简体拼音

在服务器安装 `ibus`、`ibus-libpinyin`、`ibus-gtk3` 和 `im-config`。2026-11-06 实测版本为 IBus `1.5.26-4`、`ibus-libpinyin` `1.12.1-2ubuntu2`。本次 Ubuntu 依赖归档在 `/home/browser/downloads/20261106_ibus/`。安装预演显示新增 32 个包。 [Ubuntu 的 IBus 使用说明](https://help.ubuntu.com/community/ibus)

- **当前会话。** 在 `browser` 的 XFCE 图形会话和会话总线中启动 `ibus-daemon --daemonize --xim`。将 XFCE `xsettings` 的 `/Gtk/IMModule` 设为 `ibus`。通过 IBus 的 GSettings 把 `preload-engines` 和 `engines-order` 设为 `['xkb:us::eng', 'libpinyin']`，将 `org.freedesktop.ibus.general.hotkey` 的 `triggers` 设为 `['<Control>space']`。
- **以后登录。** `/home/browser/.xinputrc` 在 Xsession 的第一阶段选择 IBus。`/home/browser/.xsession` 导出 `GTK_IM_MODULE=ibus`、`QT_IM_MODULE=ibus`、`XMODIFIERS=@im=ibus`，并在 XFCE 使用的独立 D-Bus 会话内启动 IBus 与桌面。这样输入法守护进程与应用使用同一图形会话。
- **ChatGPT 桌面图标。** `/home/browser/Desktop/ChatGPT.desktop` 的 `Exec` 为 `env GTK_IM_MODULE=ibus QT_IM_MODULE=ibus XMODIFIERS=@im=ibus chatgpt %U`。从该快捷方式重开时会带入输入法环境，现有桌面会话也可使用。
- **日常使用。** 在输入框按 `Ctrl + 空格` 在英文和简体拼音之间切换。也可在服务器桌面的 IBus 指示器选择 **Intelligent Pinyin**。本次通过 IBus 输入上下文验证 `nihao` 加空格提交了「你好」。ChatGPT 旧窗口仍只显示英文字母时，按故障排查页处理。 [ChatGPT 旧进程排查](故障排查.md#chatgpt-linux-ibus-relaunch)

<a id="winscp-sftp-648343228"></a>
### 用 WinSCP 双向传输本机与服务器文件

双击项目下的 `output/20261103_winscp/Open-WinSCP.cmd`。WinSCP 6.7 安装于 `C:\env\winscp`，使用中文双栏界面。站点通过 SFTP 连接 `64.83.43.228:22`，账号为 `browser`。启动入口使用通过可信 SSH 连接核对的 ED25519 主机指纹，并从本机 Windows DPAPI 加密凭据文件读取登录信息。

| 方向 | 操作 | 默认接收目录 |
|---|---|---|
| 上传到服务器 | 从左栏拖到右栏 | `/home/browser/downloads/` |
| 下载到本机 | 从右栏拖到左栏 | 项目内 `downloads/server_transfer_64.83.43.228/` |

默认复制文件，源文件保留。可以用两侧的地址栏切换目录。要把服务器 Chrome 下载的文件拿回本机，直接从右栏的 `/home/browser/downloads/` 拖到左栏。要取服务器桌面文件，在右栏切换到 `/home/browser/Desktop/`。

2026-11-03 已实测登录、浏览服务器目录，并上传后下载一个 141 字节的中文文件名测试文件，往返 SHA-256 一致。证据在 `output/20261103_winscp/transfer-verification.json`。需要复验时，用 Windows PowerShell 5.1 运行同目录的 `Test-Transfer.ps1`，因为当前安装的 WinSCP .NET 程序集面向 .NET Framework。脚本会生成测试文件和日志。

<a id="winscp-folder-relocation"></a>
### WinSCP 配置文件夹能否单独移动

`output/20261103_winscp` 目前依赖原有项目布局。仅复制或移动这个文件夹后，一键入口会找不到原有凭据，下载或日志路径也可能改变。依赖来自以下位置。

| 依赖 | 当前配置 |
|---|---|
| Windows DPAPI 凭据文件 | `settings.json` 指向同级远程桌面目录的 `../20261103_remote_browser/desktop-login.clixml` |
| 本机下载和临时目录 | 从 WinSCP 文件夹解析 `../../downloads/server_transfer_64.83.43.228` 与 `../../temp/20261103_winscp` |
| WinSCP.ini | 本机目录、随机种子和拖拽临时目录含原项目的绝对路径 |
| WinSCP 程序 | `C:\env\winscp` |

同一台电脑、同一 Windows 用户下要把它改成可独立搬动的目录，可以让启动器按自身目录解析凭据、下载和临时路径，并在启动时重新应用本机目录和 WinSCP.ini 的临时路径。WinSCP 程序仍可从 `C:\env\winscp` 调用。换电脑或 Windows 用户时，需要在目标环境重新配置登录凭据，现有 DPAPI 文件绑定原 Windows 用户和电脑。以上为迁移方案，截至 2026-11-04 只核对了依赖，尚未改造或验证搬迁。
