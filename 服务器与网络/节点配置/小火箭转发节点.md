<a id="section-核心结论"></a>
## 核心结论

- 本工程曾生成一个 Shadowrocket 兼容的 Shadowsocks 转发节点方案。
- 服务端程序使用 `shadowsocks-libev` 的 `ss-server`，系统用户为 `ssforward`。
- 节点端口记录为 `41000`，协议为 Shadowsocks，方法为 `chacha20-ietf-poly1305`，支持 TCP 和 UDP。
- `clash-verge-direct-node.yaml` 含节点密码，属于敏感配置，不应公开复制到文档或聊天中。

<a id="section-服务端脚本做了什么"></a>
## 服务端脚本做了什么

`deploy_shadowrocket_node.sh` 的主要行为：

1. 安装 `shadowsocks-libev`。
2. 创建系统用户 `ssforward`。
3. 写入 `/etc/ssforward/config.json`。
4. 创建 nftables 防护表 `ssforward_guard`，限制服务用户访问本机、内网、链路本地、多播和服务器自身地址。
5. 创建并启用 `ssforward-guard.service` 与 `shadowrocket-forward.service`。
6. 使用 UFW 放行指定 TCP/UDP 端口。

<a id="section-防护规则目的"></a>
## 防护规则目的

防护规则的目标是让 Shadowsocks 节点只做公网转发，避免通过该节点访问服务器本机服务、内网地址或特殊地址段。

历史补丁 `fix_loopback_response_guard.sh` 增加了：

```text
meta skuid ssforward ct state established,related accept
```

其目的应是允许已建立连接的返回流量，避免防护规则误伤正常响应。

<a id="section-clash-verge-配置边界"></a>
## Clash Verge 配置边界

`clash-verge-direct-node.yaml` 是本地 Clash Verge/Mihomo 可用的 Shadowsocks 节点配置示例。它和 AmneziaWG client2 不是同一种配置：

- Shadowsocks 节点适合代理客户端使用。
- AmneziaWG 是 VPN 隧道配置。
- 两者都可能改变出口 IP，但协议、客户端和路由模型不同。
