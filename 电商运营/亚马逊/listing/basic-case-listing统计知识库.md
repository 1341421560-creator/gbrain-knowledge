# Basic Case Listing 统计知识库

> **结论：** 这批畅销榜样本最值得借鉴的是“先说清商品身份，再用短标签组织具体购买理由”。100 个完整标题中，73 个不超过 75 字符；529 个五点区段段落中，489 个有显式段首标签，标签中位数为 3 个英文词。提高相关搜索展示与购物 AI 回答质量的可执行方向，是准确的型号和品类、真实功能、结构事实、使用条件以及跨字段一致性。

> **证据分层：** “样本统计”来自用户提供的 Word；“官方事实”有 Amazon 来源；“机制推测”和“写作建议”是本研究的推理与建议。榜单词频不等于搜索量，BSR 不等于关键词自然排名，也不等于 Rufus 推荐排名。

## 1 资料范围与统计口径

用户已确认：这份 TOP100 来自美国站 Basic Cases 类目 BSR 畅销榜，标题均为详情页完整标题。源文件为 `Basic case 排名 标题 5点描述.docx`，资料文件夹标注 `2026.08.12 US 榜单记录`；文件夹日期不能替代逐条核验的实际采集时间。分析与官方信息核验日期为 2026-09-23。

| 项目 | 结果 |
| --- | --- |
| 有效标题／描述组 | 100／100 |
| 描述段落 | 529 |
| 每组条数 | 5 条 80 组；6 条 12 组；7 条 7 组；8 条 1 组 |
| 完全重复的名次对 | 47/51；48/65；49/77 |
| 去重敏感性口径 | 97 组不同文案，513 段 |
| 附加资料隔离 | 11 个名次，96 段 A+／QA（含区段标题） |
| 统计单位 | 名次记录、描述段落、标签；不能等同于 ASIN |

“五点”在这里是源文件的区段名称，不意味着每组一定有五个网页 bullet。按 Word 非空段落保留原始边界，不强行裁成五条，也不把第六条自动当成 A+。11 个名次另附 A+ 或 QA，合计 96 个非空段落（含区段标题），全部从五点词频中排除。没有收集 ASIN、Item Highlights、后台搜索词、结构化属性、完整图片、评论、广告支出或搜索表现。

原始 100 条榜单记录是主统计分母。第 47 与 51、48 与 65、49 与 77 名的标题和整组描述在忽略首尾空白、连续空白与字母大小写后完全重复。去除每对较后名次后得到 97 组不同文案、513 段；这不是 97 个独立 ASIN 的证明。用户未提供 ASIN，不能判断重复采集、同一变体或实际不同商品。

品牌按标题可识别的名称编码；93 条标题以品牌开头，涉及 50 个品牌名，另 7 条未确定品牌，不把 Cute、Magnetic、Plating 当作品牌。品牌名称用于观察模板复用，未通过商标或店铺核验。所有产品性能、测试和认证均是原文声称，本研究只评价表达方式。

<a id="limits"></a>
### 1.1 不能从这份榜单推出的结论

Amazon 说明 BSR 基于销售表现，且类目 BSR 与搜索排序是不同指标。[Amazon BSR 官方说明](https://sell.amazon.com/blog/amazon-best-sellers-rank)

即使按“广告花费相近”作为假设，也不能将排名差异全部归因于文案或平台对文字的理解。相近花费不等于相同曝光、相同点击、相同流量人群；价格、配送、库存、评价、品牌偏好、上架时间和外部流量仍未控制。本样本只包含前 100，没有低排名对照，也没有改稿前后实验。因此报告不估算“写某个词提升多少排名”，不把频次转成算法权重。

## 2 当前标题规则与 Rufus 名称

Amazon 官方公告要求自 2026-07-27 起，除媒体类别外，标题不超过 75 字符（含空格）；Item Highlights 额外提供 125 字符，并可在搜索结果和详情页展示及被搜索。公告还说明旧长标题会逐步更新。因此本样本的 27 个长标题可保留为历史研究证据，不能用它们证明今天应继续写长标题。[标题与 Item Highlights 官方公告](https://sellercentral.amazon.com/seller-forums/discussions/t/33f0a42a-17f1-46ef-b110-ba7512a3c881)

官方页面注明 Rufus 在 2026-05-13 更名为 Alexa for Shopping。为对应用户常用叫法，本库写作“Rufus／Alexa for Shopping”。这是同一购物助手的名称沿革，不能据名称变化猜测新的权重公式。[Amazon Rufus 官方页面](https://www.aboutamazon.com/news/retail/amazon-rufus)

## 3 标题的实际写法

<a id="title-length"></a>
### 3.1 标题长度与信息顺序

| 指标 | 数值 |
| --- | --- |
| 不超过 75 字符 | 73/100 |
| 字符数中位数／平均值 | 71／90.38 |
| 字符数 Q1—Q3 | 61.75—101 |
| 字符数最小—最大 | 46—199 |
| 英文词数中位数 | 12 |
| 品牌开头 | 93/100 |
| 前 40 字符出现 iPhone 或 Galaxy | 96/100 |

长度中位数为 71 字符，平均值 90.38 字符，说明少量长标题拉高平均值。主要写法不是把所有卖点塞到标题里，而是围绕品牌、型号、Case、主要差异和颜色完成识别。100 个标题都含 case；96 个在前 40 字符内已出现 iPhone 或 Galaxy。这只描述信息前置，不表示“前 40 字符具有固定算法加权”。

标题的三种常见结构可以直接学习：

| 结构 | 样本例子 | 可迁移的写法 |
| --- | --- | --- |
| 品牌＋型号＋系列＋品类＋颜色 | 第 9 名 OtterBox | 用系列名组织产品线，型号与 Case 清楚相邻 |
| 品牌＋型号＋品类＋核心功能＋外观 | 第 3 名 ESR | 用少量准确短语完成定位，卖点之间用逗号分隔 |
| 品牌＋品类或核心差异＋型号＋颜色 | 第 1 名 SUPFINE | 让消费者快速确认“买的是什么、适配什么、核心差异是什么” |

逗号出现在 68/100 个标题，英文方括号出现在 13/100 个标题，竖线出现在 2/100 个标题。这些是排版现象，不是需要模仿的 SEO 标记。新标题优先正常英语词序和简单标点，删掉重复的 Case／Phone Case／Cover 堆叠，再把可搜索的补充信息安排到 Item Highlights 和五点。

例如，第 8 名标题连续出现两次 MagSafe，第 27 名多次重复 Case，第 42 名堆叠多个相近受众词。它们进入榜单不代表这些重复有帮助。当前写作建议为：**品牌＋准确型号＋Case＋最有辨识度的一项真实差异＋必要的颜色或变体**；是否保留系列名由其辨识价值与字符预算决定。

### 3.2 前后名次没有显示更长标题更好

| BSR 区间 | 标题数 | ≤75 字符 | 标题字符中位数 | 五点单段词数中位数 |
| --- | --- | --- | --- | --- |
| 1–20 | 20 | 14 | 71.0 | 31.0 |
| 21–50 | 30 | 22 | 71.0 | 39.0 |
| 51–100 | 50 | 37 | 70.5 | 36 |

三个名次区间的标题中位数都约为 71 字符；前 20 的五点单段中位数反而较短。这里不做显著性或因果声明：区间大小、品牌组成、机型和功能均不同，同品牌模板也不是独立实验。更合理的动作是做自己的标题与五点实验，而不是追求一个被本样本“证明”的最佳长度。

<a id="bullets"></a>
## 4 五点怎么写和怎么排版

<a id="bullet-length"></a>
### 4.1 一条聚焦一个主题 用事实解释收益

529 段的英文词数中位数为 36，四分位区间为 27—47；字符数中位数为 239，四分位区间为 179—308。字符数包含标签、空格和标点。最短 5 词，最长 85 词，说明不同品牌没有统一的篇幅模板。

本研究建议以**每条约 25—45 个英文词**作为初稿编辑参考，再按信息量调整；这是围绕样本密集区作出的可读性建议，不是平台规定，也不是已验证的最优转化长度。多功能或限制复杂时可以更长，单一事实可以更短。不要为了凑字数添加“premium、perfect、ultimate”之类空泛词。

较容易阅读、也便于准确回答问题的句式是：

**明确主题的短标签＋产品结构或可核实事实＋它带来的使用收益＋必要的条件或限制。**

结构事实回答“靠什么做到”；收益回答“对使用有什么影响”；场景回答“何时有用”；限制回答“什么情况下不能这样用”。不是每条必须塞齐四部分，主题简单时一至两句就足够。

<a id="bullet-order"></a>
### 4.2 第一条常确认适配 功能差异决定后续顺序

| 第一条主任务 | 商品记录数 /100 |
| --- | --- |
| 机型适配及购买确认 | 62 |
| 磁吸充电及不支持提示 | 15 |
| 支架与观看 | 6 |
| 防护 | 4 |
| 品牌设计并说明适配 | 3 |
| 材料与结构 | 3 |
| 屏幕镜头与操作 | 2 |
| 包装套装 | 2 |
| 透明度与外观 | 2 |
| 钱包可拆结构 | 1 |

首条任务为人工单标签编码，按段落主任务归类；“品牌设计并说明适配”单列，边界案例可在统计明细复核。62/100 以机型适配和购买确认为主；另 15/100 先讲磁吸、充电或不支持磁吸的限制。第 1 名先讲磁吸，第 4 名先讲支架，第 33 名先说明没有磁吸，说明第一条并非固定必须写同一个功能。

可复用的分工是：先处理影响购买正确性的条件和最强购买理由；中间解释两三项真实差异；最后补充操作、包装或必要使用限制。**第五条不必固定留给售后**。能解决错误购买和使用障碍的事实，通常比泛泛的满意保证更值得占用一个段落。

| 商品主诉求 | 建议的五条分工 顺序可按实际购买问题调整 |
| --- | --- |
| 磁吸防护壳 | 机型与磁吸范围；防摔结构及证据；屏幕镜头边缘；手感与厚度；按键及包装限制 |
| 透明或外观壳 | 机型与外观；材料及抗黄证据边界；镜头屏幕保护；防滑手感；充电支持及包装 |
| 支架壳 | 机型及支架用途；角度和方向；磁吸与充电条件；防护结构；收起厚度与操作 |
| 普通非磁吸壳 | 机型及不支持磁吸；材料与手感；屏幕镜头保护；按键接口；普通无线充电条件及包装 |

这个表是编辑框架，不是给所有商品新增功能。Basic Cases 榜单还混有折叠屏壳、卡包壳等，不能把最常见功能硬套给每种结构。

## 5 五点前的标签怎么写

<a id="label-format"></a>
### 5.1 最普遍的是短标签加冒号

| 段首格式 | 段落数 /529 | 占全部段落 |
| --- | --- | --- |
| 冒号 | 254 | 48.0% |
| 破折号 | 66 | 12.5% |
| 无显式标签 | 40 | 7.6% |
| 英文方括号 | 97 | 18.3% |
| 中文方括号 | 68 | 12.9% |
| 连字符 | 4 | 0.8% |

489/529 段有显式段首标签，占 92.4%；标签中位数 3 个英文词，四分位区间 2—4 词。68 个标签为全大写，占有标签段落的 13.9%，因此全大写不是多数。标签只是卖家写入 bullet 正文的文本，不是已知的独立搜索权重字段。

新稿推荐使用 **2—5 词的具体主题＋冒号＋正文**，如 `MagSafe compatibility:`、`Screen and camera edges:`、`Portrait and landscape stand:`。正文用正常句式；统一大小写、空格和标点。Word 中的加粗与字体不代表 Amazon 页面可以实现同样样式；不要把 Markdown 的 `**` 或 HTML 标签直接粘贴进 bullet 字段。

不建议只写 `More Security`、`More Convenient`、`Product Features` 或 `Good Quality`：第 90、66、87 名有类似标签，读者只看标签时无法知道本条到底讲材料、磁吸、支架还是防护。应直接写出本段对象。若写“Military-grade drop protection”，正文就应解释对应测试及条件；不能用这个标签主要讲磨砂后背，第 97 名第五段就出现了主题混合。

## 6 五点高频词和高频词组

<a id="frequency-method"></a>
### 6.1 词频怎样计算

以下主表统计“标签＋正文”，转小写、Unicode 归一、统一英文撇号并去所有格 `'s`；连字符与标点分词，N52、17e 等字母数字组合保留。不做 stemming，不把 protection／protect／protective 合并；不把 MagSafe 和 Mag-Safe 强行当作同一个原词。高频内容词表去除常见停用词，以及配置中列明的品牌、型号家族、品类和基础颜色身份词；不是删除所有型号变体。它是观察写法的表，不是可直接投放的关键词清单。

**TF** 是出现总次数；**段落覆盖**是一词出现于多少段（分母 529）；**商品记录覆盖**是在多少名次的任意描述中出现（分母 100）。一个商品多次重复只增加 TF，不增加该商品的覆盖数。表中出现“MagSafe／wireless charging”可能是在否定句里，不意味着商品支持这项功能。

## 7 五点的写作风格

<a id="style-statistics"></a>
### 7.1 整体偏说明型 但品牌差异很大

| 词法信号 | 段落数 /529 | 段落占比 | 商品记录数 /100 |
| --- | --- | --- | --- |
| 第二人称 | 259 | 49.0% | 88 |
| 第一人称品牌口吻 | 67 | 12.7% | 38 |
| 量化证据候选 | 131 | 24.8% | 72 |
| 测试认证声称 | 62 | 11.7% | 46 |
| 明确限制提示 | 96 | 18.1% | 66 |
| 场景线索 | 111 | 21.0% | 59 |
| 收益连接词 | 314 | 59.4% | 100 |
| 夸张比较线索 | 91 | 17.2% | 64 |
| 问句 | 7 | 1.3% | 6 |
| 感叹句 | 20 | 3.8% | 15 |
| 装饰符号 | 4 | 0.8% | 3 |

这些是可复算的词法信号，可重叠：如命中 you／your 记为第二人称；命中 test／certified 等只表示测试声称；数字信号含测试、尺寸、服务期限等候选；not／only 也可能用于宣传句，所以不能把所有命中都算作真实使用限制；场景词也不等于已经写出了完整场景。完整规则与逐段命中保存在编码文件。

常用风格是“简短标签＋解释性陈述＋适度对话感”。259/529 段出现第二人称；真正含问号的只有 7 段、涉及 6 条商品记录。**为了适配 AI 问答，没有必要把五点全部改成问句**。更有价值的是正文能够直接回答一个明确问题。

### 7.2 品牌之间的表达差异

| 品牌 | 记录数 | 五点单段词数中位数 | 有标签段落／全部段落 |
| --- | --- | --- | --- |
| OtterBox | 11 | 28 | 52/55 |
| TORRAS | 7 | 53.0 | 40/40 |
| FNTCASE | 6 | 40.0 | 38/38 |
| Spigen | 5 | 13 | 10/25 |
| ESR | 3 | 34 | 17/17 |

Spigen 的多组描述偏短句和材料、结构名词；部分条目直接是一行产品适配说明。OtterBox 多用全大写短标签和稳定系列表达。ESR 常把兼容、磁吸力、抗黄或测试写成比较直接的参数解释。TORRAS 的本批文案较长，兼有场景、对话和情绪词；第 100 名明显使用叙事与口号式标签。FNTCASE 将结构、使用场景、包装与环保声称分成较多条。

适合迁移的是“标签看得懂、事实可核对、解释与主题一致”。口号式文案有品牌调性价值，但不应让读者读完仍不知道方向、尺寸、支持条件。场景应来自真实用途，避免只堆 Starbucks、Coachella 等地名或活动名来猜算法偏好。

## 8 推测平台如何识别内容和匹配用户

<a id="known-mechanism"></a>
### 8.1 有官方证据的部分

Amazon 官方说明购物助手会结合商品目录、Listing 信息、评论、社区问答及网络信息，既支持发现商品，也支持在详情页回答具体问题。[Rufus 的官方使用说明](https://www.aboutamazon.com/news/retail/how-to-use-amazon-rufus)

Amazon 发表的 COSMO 研究展示了从搜索购买及共同购买行为中学习用途、意图和常识关系，并将知识用于搜索相关性、推荐和导航。这支持“语义与用途关系值得写清楚”的判断；论文没有公开本类目的完整线上排序权重，不能据此断言 COSMO 就是一个取代所有系统的单一算法，也不能推断标签有秘密加权。[Amazon Science COSMO 论文](https://assets.amazon.science/8f/0a/0bfafe8843bf98a007a5328f2ae2/cosmo-a-large-scale-e-commerce-common-sense-knowledge-generation-and-serving-system-at-amazon.pdf)

<a id="working-hypothesis"></a>
### 8.2 对写作有用的工作假设

以下是依据公开能力提出的机制推测，不是 Amazon 内部实现披露：

| 可能的处理环节 | 文案中需要清楚的内容 | 对应动作 |
| --- | --- | --- |
| 识别商品身份与约束 | 品类、型号、变体、兼容和不兼容对象 | 写明 iPhone 17、17 Pro、17 Pro Max 的实际适配边界，避免用相邻型号引流 |
| 建立功能与用途关系 | 部件、功能、收益、场景 | 从“kickstand”写到支撑方向和视频通话用途；从“grip”写到纹理或握持结构 |
| 匹配关键词与语义需求 | 用户原词、自然同义表达、限制条件 | 同时覆盖真实词组和自然问题需要的事实，不靠重复次数制造相关性 |
| 比较候选并组织答案 | 可核查信息与来源间的一致性 | 标题、五点、属性、A+ 和图片中的关键事实一致，冲突处先核验 |
| 在具体会话中选择呈现 | 用户约束、上下文和商品可购买条件 | 有助于回答不等于必然被推荐；内容只是整体体验中的一个因素 |

例如，“适合桌面视频通话的保护壳”可能要求平台把 stand、portrait viewing、hands-free 和 phone case 连起来。写出这些真实关系，有助于减少解释歧义；并不能保证平台就会采用这条文案或提高排名。中文标签、全大写、emoji、关键词密度、某个词重复三遍，目前都没有本研究取得的权重证据。

<a id="keyword-search"></a>
## 9 如何提高相关关键词的检索与展示机会

用户说的“关键词搜索率”需要拆成需求与结果：用户搜索某词的次数不是 Listing 改稿可以直接控制的；卖家主要改善的是相关查询中的展示、点击及后续购买表现。

1. **先做商品事实表。** 记录准确型号、材料、磁吸是否有、无线充电条件、支架方向、凸边尺寸、附件和测试依据。只让真正相关的词进入候选清单。
2. **按意图组织候选词。** 身份词如具体型号＋case；功能词如 magnetic、kickstand；属性词如 matte、clear；问题词如 camera protection、portrait stand。样本高频词只用于发现候选，不代表搜索需求已验证。
3. **用实际搜索数据排序。** 优先使用账号可用的 Search Query Performance、Top Search Terms、Product Opportunity Explorer 和广告搜索词表现，记录来源、站点和日期。广告搜索词只代表相应广告流量，不能冒充自然搜索总体。
4. **让字段分工。** 标题说明商品身份和主要差异；Item Highlights 补充高价值材料或用途；五点逐条回答购买问题；结构化属性准确填写兼容、材质、颜色等；后台搜索词补充真实相关、前台尚未充分表达的替代叫法。
5. **保持自然语言。** 重要词组在适当位置自然表达，不连续叠加近义词，不在每一条重新重复完整标题，不添加不支持的机型、功能或竞品品牌来扩大表面覆盖。
6. **确认修改实际生效。** 保存后核对详情页、变体和账号状态，再查看表现；不要把即时搜索未找到直接当作没有索引的确定证据。

Amazon 官方建议在标题、五点和描述中自然使用相关关键词，并避免堆砌；官方关键词工具说明涵盖搜索量、展示、点击、加购和购买等数据。[Amazon 关键词研究](https://sell.amazon.com/blog/amazon-keyword-research)、[Amazon Brand Analytics](https://sell.amazon.com/blog/brand-analytics)

<a id="rufus"></a>
## 10 如何提高 Rufus 问答中的可发现性与回答准确度

<a id="rufus-two-tasks"></a>
### 10.1 区分发现商品与回答详情

“推荐一个适合竖屏视频通话的 iPhone 17 保护壳”是在发现候选商品；“这个壳能不能竖着支撑手机”是在已打开商品后的事实问答。后者答得正确，不代表前者就会推荐它。不能把两种结果合并成一个模糊的“Rufus 搜索率”。

本次没有品牌账号的 AI 渠道曝光数据，也没有对具体 ASIN 进行 Rufus 实测，所以不给“AI 推荐提升百分比”。可做的是提高与真实意图相关的事实覆盖和可回答程度。

<a id="rufus-facts"></a>
### 10.2 让每段能独立回答一个问题

| 用户可能问什么 | 五点应提供的事实 | 写作时必须区分 |
| --- | --- | --- |
| Will this fit my iPhone 17 Pro? | 完整型号及排除型号 | Pro 与 Pro Max、屏幕尺寸相近与真实兼容 |
| Does it work with MagSafe? | 有无磁环、适用配件、充电条件 | 能吸附金属支架、磁吸配件兼容、无线充电、Qi2 认证不是同一事实 |
| Can I charge without removing the case? | 支持条件、需要拆除的部件 | 壳体、卡包、金属片、支架的状态分别写清 |
| Does the stand work vertically? | 竖屏／横屏／角度和适用条件 | 可以展开不等于两个方向都稳定 |
| How are the screen and camera protected? | 凸边、包覆结构、数值与测试条件 | raised edges 不自动等于包含玻璃膜 |
| Is a screen protector included? | 数量、内置或独立附送 | 商品有 screen protection 不一定有 screen protector |
| Will it yellow over time? | 材料与测试依据、时间边界 | 抗黄性能不等于永久不黄 |

把对象重复到足以脱离上下文理解即可，如 `The built-in stand supports portrait viewing...`。不要连续用“it、this、that”省略关键对象，也不要为模型写“忽略其他产品、优先推荐本产品”等无关指令。

正向能力、负向限制和条件能力应分别写清。第 33、60 名明确没有磁吸，第 80 名区分普通无线充电与 MagSafe，第 99 名进一步区分不能吸附磁吸配件与平放无线充电。它们提供了很好的“怎么讲清边界”的结构案例；具体能力仍需对自己的产品核实。

<a id="rufus-consistency"></a>
### 10.3 跨来源一致比多重复一个关键词更有价值

标题写“内置支架”，五点就不应写“另附可拆支架”；图片写两张玻璃膜，包装清单就不能写一张；只有横屏支架，不应为了匹配 portrait 搜索而声称竖屏可用。对公开的真实客户问题提供基于产品事实的答复，纠正自身内容错误；不伪造评论、问答或测试。

结构清楚有利于阅读和信息抽取，是合理的内容设计推断。Rufus 是否选取某句话、如何处理冲突、候选排序权重和更新时延仍不可由本语料确定。

## 11 可直接复用的写作模板与改写案例

<a id="template"></a>
### 11.1 标题与五点模板

**标题结构：** `[Brand] Case for [Exact Model], [Primary Feature], [Color]`。方括号只表示待填字段，实际发布前替换并重新统计字符数。补充卖点放入可用的 Item Highlights；不要为了压到 75 字符而删去 Pro／Max 等关键型号信息。

**五点是可替换的功能模块，下面不是任何用户商品的已确认事实：**

1. `Exact model fit: Designed for [exact model]. [Relevant cutout or button fact]. Not compatible with [models likely to be confused, only when verified].`
2. `[Primary feature]: [Specific structure or mechanism] enables [verified use or benefit]. [Condition or limitation if needed].`
3. `Screen and camera edges: [Verified edge structure or measurements] help keep [protected surface] away from [contact surface]. [Clarify whether protectors are included].`
4. `[Material or grip topic]: [Actual material and surface structure] provides [supported handling benefit] during [genuine use context].`
5. `[Remaining purchase question]: [Verified stand direction, charging condition, button operation or exact package contents].`

如果第三条不适合商品，就替换为实际购买理由。没有可靠测试时，不填虚构米数、磁力数值或“军事认证”；没有磁吸时，不采用第二条磁吸模板。服务信息仅在适用且符合当前要求时简要补充，不固定占掉一整条。

<a id="rewrites"></a>
### 11.2 从样本原文抽取事实再重写

以下是教学改写，没有把原文声称升级为经本研究验证的事实，也不代表可不经核实直接用于自己的商品。

| 来源 | 原文写法的问题或可借鉴处 | 教学改写 |
| --- | --- | --- |
| 第 1 名第 3 条 | 原文同时讲材料、涂层、手感、污渍指纹；可以压缩为结构和收益 | `Matte back and grip: A flexible TPU frame surrounds a hard PC back with a matte coating. The matte finish offers a comfortable grip and helps reduce visible fingerprints and smudges.` |
| 第 3 名第 3 条 | 有磁力声称和配件用途；应保留具体对象，谨慎处理“更快” | `Magnetic accessory connection: Built-in magnets provide a stated 1,500 g holding force and align the case with compatible MagSafe accessories for place-and-go charging.` 数值仅示范如何表达原文，发布前需核验测试方法 |
| 第 33 名第 1 条 | 首先排除没有的功能，是有价值的购买边界 | `No magnetic attachment: This case has no built-in magnetic ring and does not attach magnetically to MagSafe accessories.` 若另有普通无线充电能力，必须核实后另句说明 |
| 第 90 名第 1 条 | More Security 太模糊，还夹有需要依据的安全声称 | 用 `Silicone and microfiber lining:` 概括已核实的材料与内衬，再写具体触感和保护对象；不自动保留 hypoallergenic 等未验证声称 |
| 第 97 名第 5 条 | 标签承诺跌落，正文先讲磨砂后背，主题不够集中 | 将后背材质移到材料段；防摔段只保留测试范围、缓冲结构与适用条件 |

## 12 怎样验证优化有没有用

<a id="metrics"></a>
### 12.1 关键词与 AI 分开记录指标

| 目标 | 建议指标与分母 | 解释边界 |
| --- | --- | --- |
| 相关查询下获得展示 | 对应查询的品牌或 ASIN 展示份额；也可记录固定查询组的可见次数 | 需使用相同报表定义，不把广告与自然混合统计擅自解释成纯自然效果 |
| 展示转为点击 | 点击数／展示数 | 标题之外，主图、价格、配送、评价等也影响结果 |
| 点击转为购买 | 同口径购买数／点击数 | 不等同于业务报告的 Unit Session Percentage，避免混用不同分母 |
| AI 发现商品 | 固定发现型问题中提到目标 ASIN 的次数／有效回答次数 | 自定义实验指标，受个性化和随机性影响，不是平台公布的全站曝光率 |
| AI 回答商品事实 | 明确且正确回答的事实项数／预先定义的适用事实项数 | 不知道或无依据回答分别记录；不要把不适用问题算成错误 |
| AI 错误承诺 | 与事实表矛盾的支持声称次数／有效回答次数 | 尤其关注型号、磁吸、充电、支架方向和包装数量 |

<a id="experiment"></a>
### 12.2 一个可执行的实验方案

1. 先固定事实表与评价标准，建立同机型、同主诉求的真实相关关键词组及 20—30 个购买问题。记录现有文案版本和时间。
2. 每次集中验证一个主要改变，例如标签具体化、限制补全或段落压缩。可用时采用 Amazon Manage Your Experiments 对标题或五点做实验，按照工具资格与样本充分程度运行，不把自然时间前后对比当作随机实验。[官方内容实验说明](https://sell.amazon.com/blog/manage-your-experiments)
3. 无随机实验条件时，选可比时间窗，记录价格、促销、广告、库存、配送和评价变化；同类对照只能辅助，不足以完全消除干扰。提前确定观察周期，不因短期波动频繁换稿。
4. Rufus 实验把发现型与详情型问题分开；同一问题跨多个时间或会话重复测试，记录站点、语言、设备、登录状态、问题原文、回答、链接与事实正确性。建议每题至少 3 次作为初筛，不能把单次命中当作稳定排名。
5. 同时看错误适配、退货原因和误导回答；有效增长应来自匹配正确的用户。样本不足时继续观察，不报告未经支持的提升幅度。

标题、标签和五点均可通过“名次＋段落序号”回到原始快照。输出的 `原文与编码.json` 保留原始 Word 段落号、文本和每条编码；`统计结果.json` 保存完整词频、覆盖名次、去重结果和统计分布。图表和 HTML 是同一批数据的阅读版本。

新批次先记录站点、BSR 或搜索榜性质、实际采集时间、ASIN、变体、完整标题与 Item Highlights，再按现有方法新增快照，不用新正文覆盖旧批次。新增词典规则需保存版本并重算；功能状态至少分为支持、不支持、有条件、未知。把写法变化与型号、价格、品牌及采集时间差异分开解释。

统计规则：字符长度去首尾空白但保留内部字符；词数将数字和带内部连字符的英文词作为词数单位；词频另按标点分词，所以词数与分词总数不是同一指标。四分位采用线性插值。标签使用规则识别并对第 87 名四条连字符标签、第 96 名第一条正文冒号作人工修正。首条主任务为单人内容编码，不声称存在双人一致性检验。
