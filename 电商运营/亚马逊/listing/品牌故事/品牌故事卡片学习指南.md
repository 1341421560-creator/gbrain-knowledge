# 品牌故事卡片学习指南

> **用途：** 这是一套通用的品牌故事卡片学习知识库，用来研究不同品牌怎样安排卡片、组织文案、呈现产品与建立视觉一致性。记录样本观察、可学习的方法和适用条件，供后续品牌研究与内容设计时参考。

素材来自「2026.09.19 X系列品牌故事」目录：20 组样本、19 个不同品牌、72 张截图和 20 份文字。TORRAS 有两组版本，分别保留。72 张截图是横向浏览过程中的页面截屏，含有重叠内容，**不能当作 72 张独立卡片**。

**2026-10-06 补充：** 本指南同时收录平台规则、图片规格、Q&A 两种做法、发布排查与卖家历史案例。样本出现某种写法，不代表平台允许该写法；品牌自述、平台规定、历史后台截图和设计建议分别标明。平台知识从[第 11 节](#platform-scope)开始。

<a id="scope"></a>
## 1. 学习对象与证据范围

学习对象是样本中的品牌故事背景与内容卡片。样本覆盖保护壳、钱包壳、斜挎款、磁吸支架壳及相关配件，不把整个知识库限定为某一种产品结构。

需要分别记录三层信息：截图实际呈现的内容、品牌在素材中的自述，以及分析者归纳出的可学习方法。样本未提供转化率、对照实验或经过核验的排名，不能据此确认某种卡片设计一定带来更高销量。

文件夹日期是资料标记，不能直接当作每张截图的采集日期或页面发布日期。未单独核验样本中的销量、专利、测试、认证、合作、环保及服务声明。

## 2. 品牌故事卡片的共同点

| 共同点 | 样本中的表现 | 可以学习的方法 |
| --- | --- | --- |
| 有持续出现的核心主张 | SHIELDON 的便利、ESR 的易用、Smartish 的日常轻松、Strapurs 的随身便利 | 观察主张能否在后面的产品、场景和细节中得到解释 |
| 背景贯穿横向卡片 | 20 组样本均有贯穿浏览的背景，前景卡片依次展开信息 | 分清背景的识别作用和卡片的信息作用；横滑形式本身受展示模块形态影响 |
| 产品进入生活场景 | 取卡、放入口袋、佩戴、桌面使用、拍照等 | 每张场景图表达一个具体动作，减少只更换人物姿势的重复信息 |
| 色彩与视觉语言连续 | SKYEAGLE 的黑棕皮纹、Spigen 的黑橙、Smartish 的青绿色、Strapurs 的紫色 | 记录主色、背景材料、光线、字体和产品摆放如何形成一致印象 |
| 用不同内容建立信任 | 材料、结构、制造、测试、历史、服务、合作与用户内容 | 区分品牌自述、示意画面、实际过程和可核对证据，不将它们视为同等证明 |
| 内容衔接产品选择 | ESR、OtterBox、elago、Smartish、PITAKA 等安排系列入口 | 学习分组逻辑，例如用途、系列、设备或配件角色 |
| 环保是常见主题之一 | 11 组样本、去重后 10 个品牌有独立环保内容 | 比较态度表达与具体行动说明的区别，记录其与产品的相关性 |

环保统计包括 ASAFCASE、ATATOO、TORRAS 两组、ESR、Spigen、elago、OTOFLY、PITAKA、AOTESIER、Vihibii。TOCOL 的文字提及环保材料，但没有计入独立环保卡片。统计只说明内容出现，不代表真实性已核验，也不代表当前平台允许发布；环保内容应再按[第 13 节](#content-policy)检查。

<a id="card-types"></a>
## 3. 按卡片任务建立学习分类

卡片可以同时承载两种内容；分类以主要沟通任务为准，不按装饰元素机械归类。

| 卡片类型 | 主要回答的问题 | 参考样本 | 重点观察 |
| --- | --- | --- | --- |
| 品牌介绍与主张 | 品牌关注什么，为谁服务？ | SHIELDON、ESR、Smartish | 主张是否具体，介绍是否与后文关联 |
| 生活场景与人物使用 | 产品在哪个时刻有用？ | Strapurs、Cracdily、Jcxtrombulous | 动作、携带比例、使用结果是否清楚 |
| 材料与工艺 | 产品的触感、结构或制作有什么特点？ | SKYEAGLE、PITAKA、SHIELDON | 材料近景与文案是否对应；氛围图与工艺证明是否分清 |
| 功能与结构解释 | 它怎样实现某种用途？ | TORRAS、ATATOO、Vihibii | 是否用局部、展开图或动作解释机制，而非只写形容词 |
| 研发、历史与质量依据 | 品牌的能力来自哪里？ | TORRAS、TOCOL、ESR | 过程、时间线、数字和来源是否明确；与当前产品有何关系 |
| 服务与支持 | 样本怎样表达支持？ | ASAFCASE、TOCOL、OTOFLY | 仅研究其表达方式；保修保证、站外客服等内容应按[平台限制](#content-policy)检查，不能因样本存在而直接迁移 |
| 系列展示与选择 | 有哪些产品，怎样挑选？ | OtterBox、elago、ESR、Smartish | 分类依据、款式角色和入口文字是否容易理解 |
| 用户、创作者与合作 | 什么人怎样使用，品牌认同什么？ | TORRAS、AOTESIER、Spigen | 产品用途与人物故事是否连接；区分模特图、用户内容与合作自述 |
| 环保与责任 | 具体采取了什么行动？ | PITAKA、elago、ESR、OTOFLY | 是否说明材料、包装或行动，是否提供适用范围与可核对线索 |

<a id="sequence-patterns"></a>
## 4. 样本中的卡片编排方式

以下是对样本的结构归纳，不是平台规定的卡片顺序或固定数量。

| 编排方式 | 样本表现 | 学习重点 |
| --- | --- | --- |
| 生活价值带出产品用途 | SHIELDON、Strapurs 将便利主题与收纳、携带、使用场景相连 | 记录功能如何变成可看见的生活动作 |
| 材料或结构形成主线 | PITAKA 围绕材料；TORRAS 围绕支架与保护结构 | 看主张、细节解释、使用价值之间是否连贯 |
| 视觉气质带出配饰角色 | SKYEAGLE、Cracdily、Rezzoiro 强调纹理、服饰与产品协调 | 看人物与环境是否帮助理解产品气质及用途 |
| 简短介绍承接系列导航 | OtterBox、elago、ESR 将较多空间用于产品选择 | 看系列怎样分组，以及选择信息是否清楚 |
| 责任主题贯穿内容 | OTOFLY 以环境主题和服务内容构成主体 | 观察主题一致性，同时记录产品信息的覆盖程度 |

成熟品牌与产品线较少的品牌，在介绍、证据和产品入口上的篇幅分配可能不同。学习时记录这种差别，不把某一个样本的顺序设为通用模板。

<a id="visual-copy"></a>
## 5. 视觉与文案值得学习的地方

**背景承担稳定识别。** 记录品牌标识、主色和核心视觉如何贯穿浏览，同时观察背景是否与卡片内容争夺注意力。背景中的产品或人物应与前景卡片形成联系。

**一张卡片有一个清楚的重点。** 可以同时出现标题、说明和图片，但它们应共同解释同一件事。结构展开、材质近景、人物使用和系列入口承担的任务不同，需要有相应的信息层级。

**功能要与使用结果相连。** 钱包样本用取卡、携带说明收纳价值；支架样本用桌面使用或创作场景解释结构价值。学习的是功能到场景的表达方式，具体能力仍取决于对应产品。

**质感来自相互一致的细节。** 材料纹理、配色、光线、人物服装、字体和产品摆放共同形成视觉印象。单独复制某种棕色背景、金属光效或奖杯，不能复制整套表达的逻辑。

**短句应提供具体信息。** Smartish 的利益句与系列角色较明确；多个样本的高品质、创新、客户至上等介绍存在相似性。学习时标出哪些句子说明了具体用途，哪些只提供了抽象态度。

**证明方式需要分级。** 品牌声明、服务承诺、过程照片、测试结果和第三方证据的作用不同。卡片可以展示其中一种，但分析记录应说明材料实际提供到了哪一层。

<a id="copy-integrity"></a>
### 5.1 用户原始文案保真与禁词变体检查

**2026-10-06 用户补充的制作规则：未经允许，不得随便修改用户文案；禁用词的相近形式也不要使用，例如 `essential → essentials`。** 这是用户内部执行要求，与平台内容政策分别记录。

- 学习竞品的背景、光线、卡片构图和字体，不自动取得改写用户品牌故事、标题或 Q&A 的许可。用户提供或已确认的原文作为排版依据，不能自行摘要、润色、翻译或增加表达。
- 换字体、改尺寸、重新安排横版卡片和轮播等视觉请求，只授权相应视觉调整。用户要求保留全文时，逐字核对其提供或确认的文字版本，不能把助手自行改写后的摘要称为原文全文。
- 原文与禁词要求冲突时，先标出原句、实际词形、对应词项及建议改法，在用户已给出的修改授权范围内执行；没有该授权时先确认具体改法，不直接替换成图片。
- 检查用户原稿、经授权修改稿与实际图片三种材料，并记录命中来自哪个版本。助手新增的禁词不能归因于用户原稿。此类错误实例为助手改写加入 `our`，而用户原文并无该词。
- `essentials` 虽与 USA 词表的 `essential` 不是同一字符串，仍须避用。按对应站点执行原词加相近词形检查，不能仅凭精确匹配零命中判定通过；保持词边界，避免任意子串误报。
- 生成提示词给出准确原文，并要求不增删、不改写；成品仍须人工逐字核对，OCR 与脚本辅助结果不能替代原文对照。
- 用户只要求更新知识库、暂时停止图片修改时，只记录规则，现有图片和轮播留待后续明确制作请求处理。

具体匹配口径、修改授权和来源归属以[Listing 违禁词总规则](../违禁词/listing违禁词使用规则与站点索引.md#matching)、[相近词形避用](../违禁词/listing违禁词使用规则与站点索引.md#word-family)及[原稿保真流程](../违禁词/listing违禁词使用规则与站点索引.md#copy-integrity)为准。

<a id="case-06"></a>

<a id="learning-workflow"></a>
## 7. 后续怎样继续积累学习卡片

1. **先登记来源。** 记录品牌、样本版本、来源日期标记、截图文件及原文位置。
2. **完整查看横向内容。** 相邻截图可能重复出现同一张卡片，先辨认重叠，避免把截图数当成卡片数。
3. **给卡片标主要任务。** 用品牌主张、场景、材料工艺、结构、质量依据、服务、系列、用户合作或环保等分类描述。
4. **拆开文案与画面。** 分别写出标题在承诺什么、画面在展示什么，以及二者是否对应。
5. **写清可学的方法。** 例如统一材料色调、以动作解释功能、按用途组织系列；避免只记录“高级”“好看”等感受。
6. **注明适用条件和局限。** 包括产品结构、证据需求、重复信息、文字密度与素材缺漏。
7. **链接回原始证据。** 保留品牌、组号和截图编号；有新增版本时分别登记，再比较变化。

单条学习记录可按以下字段整理：**来源 → 卡片类型 → 沟通任务 → 文案与画面 → 可学方法 → 适用条件 → 局限 → 原图链接**。这是研究记录结构，卡片成品数量和样式不由此固定。

<a id="tradeoffs"></a>
## 8. 不宜直接迁移的内容

| 情况 | 分析时怎样处理 |
| --- | --- |
| 大段通用品牌形容词 | 标出实际提供的信息，判断是否与产品或用户需要有关 |
| 多张近似人物肖像 | 对比每张新增了什么信息，不能只按画面数量判断丰富度 |
| 复杂历史、技术或奖项堆叠 | 记录其与品牌主张及当前产品的联系，不以数量替代关联性 |
| 大量产品并列 | 观察有无明确分组、角色与选择依据 |
| 环境符号与泛化承诺 | 区分态度画面和具体行动说明 |
| 排名、销量、材料、性能、认证或服务数字 | 作为该品牌的原文声明保存，不转成未经核验的通用事实 |
| 不同版本的数字或表述 | 分别保存版本，注明差异，不拼成单一时点的结论 |
| 竞品已上线但涉及平台限制的内容 | 保留原始证据；先检查平台是否允许，再考虑事实支持，不能仅以“竞品在用”或“有证据”为发布依据 |

当视觉借鉴涉及商品造型、花纹或凹槽时，可按[商品图片外观专利查询流程](../../选品/商品图片外观专利查询流程.md)先做目标市场的设计权利初筛。借鉴图片排版、拥有图片使用权与商品设计不侵权是不同问题；该流程案例尚未确认图片对应专利，不能当作销售许可。

| 原生 Brand Q&A | 在模块文字字段中填写 | 由平台生成文字卡片，无须导出为 362 × 453 px 图片。 |
| Logo、ASIN 展示等卡片 | 按各自上传框要求 | 不把焦点图片卡规格统一套到所有卡片，也不将整张卡片的显示尺寸当作内部小图尺寸。 |

图片文件使用 JPG、PNG 或 BMP，RGB 色彩模式，单张小于 2 MB；官方要求至少 72 dpi，同时仍需满足模块像素要求。禁止动态图、CMYK、二维码及水印，避免模糊图与手机端不可读的小字。依据：S3、S4。

**制作压缩建议（非平台要求）：** 独立图片卡约 100～500 KB、背景约 300 KB～1 MB。这两个范围是压缩目标，不是平台硬性上下限；小于建议范围无需增大文件，高于建议范围也不必为了数字继续损伤画质，但必须符合单张小于 2 MB 的要求。

**桌面与手机的素材关系：** 焦点图片卡通常使用该模块上传的同一张图片，在两端分别排版显示；移动端独立上传指的是贯穿背景。应在当前模块预览中确认显示与裁切，不要把移动端背景规格套到图片卡。

**像素与压缩不能混为一谈：** px 决定图片像素数量，KB/MB 是文件体积，dpi 元数据不能恢复原图细节。加倍放大低清图片不保证清晰。设计时保留清晰原稿，按比例导出，并以手机预览可读性检验成品。这些是制作建议。

<a id="qa-cards"></a>
## 12. Q&A 原生卡片与自行设计的图片卡

<a id="native-qa"></a>
### 12.1 原生 Brand Q&A

品牌故事支持原生 Brand Q&A；无需先开通高级 A+。后台一般路径为 A+ Content Manager → 创建 Brand Story → 添加模块 → Brand Q&A。菜单位置随站点和界面版本变化，以实际入口为准。依据：S2、S8。

历史模块支持最多三组问答，可用预设问题或自定义问题；具体字符上限以当前输入框与校验提示为准，不把网上的“六百字符”或“七百五十字符”统一写成所有站点当前规则。

原生卡片由品牌在后台填写问答、由平台排版。品牌问答与引用普通顾客评价是不同内容形式；整理顾客关心的主题后，可以用品牌口吻准确作答，仍要遵守内容政策。

适合的主题包括品牌创立背景、想解决的需求、设计理念及有事实依据的产品特点。这是内容建议，平台不强制使用固定的三个问题。

<a id="image-qa"></a>
### 12.2 把 Q&A 直接设计成图片卡

可以考虑将问题和答案排进图片，以 Brand Focus Image 作为普通图片内容提交。**证据边界：** 截至本次核对，没有查到专门禁止 Q&A 图片格式的条文；这是依据模块能力与内容规则作出的实践判断，不是平台对该做法的专项许可，也不保证审核通过。

图片卡按焦点图片规格和单张文件限制制作；问题、答案、图标与图片中所有文字都受同一内容审核约束。图片里的文字不是额外的政策豁免。

S5 建议减少图片内嵌文字，使用模块文本以提高手机可读性。建议一张图片卡放一个问题和一个简短答案，答案一至两句，字号有层级并留足边距；问答较长时优先原生模块。该数量与句数为设计建议，不是平台要求。

| 选择条件 | 优先方案 |
| --- | --- |
| 问答较长，后续经常改文案，希望使用平台文字排版 | 原生 Brand Q&A。 |
| 内容短，整套需统一自定义字体、配色和视觉版式 | 可考虑 Q&A 图片卡，检查手机可读性并按普通图片审核。 |

## 13. 禁止事项、证据要求与特殊例外

<a id="policy-restrictions"></a>
### 13.1 内容与隐藏字段检查

以下为 S3 政策的简要检索表；有特殊产品或类目时回查原文，不凭这张表判断全部例外。

| 检查项 | 限制 |
| --- | --- |
| 价格与促销 | 禁价格、折扣、赠品、促销及催购文字。 |
| 配送与保证 | 禁配送、保修、满意保证及站外退货退款政策。 |
| 联系与引流 | 禁站外网址、二维码、电话、地址、邮箱及站外客服。 |
| 卖家授权 | 禁“只有我们出售正品”等卖家或授权声明。 |
| 竞品比较 | 禁点名或影射竞品；同品牌对比可用相应模块。 |
| 排名与夸耀 | 禁 best-selling、top-rated 等排名或夸耀宣称。 |
| 医疗功效 | 禁治疗、缓解、预防疾病等受限宣称。 |
| 环保 | eco-friendly、biodegradable、compostable 受禁；recyclable 等需支持。 |
| 认证与奖项 | 注明机构、证据和年份；不提超过两年的奖项。 |
| 引用背书 | 禁普通顾客和私人评价；公众人物或出版物引用另有条件。 |
| 格式与符号 | 限制混用语言、HTML、全大写；正文移除商标版权符号。 |
| 平台仿冒 | 禁仿亚马逊标识、界面标题和平台信息。 |
| alt-text | 必须描述图片；不相关关键词可能拒审。 |

此外，S3 要求仅包含一个品牌 Logo，图标应帮助理解；合理大小的包装或固定 Logo 内商标符号有条件允许。S5 要求拥有素材使用权。不要因为有事实依据、已注册商标或竞品仍展示某种写法，就跳过政策准入检查。

<a id="policy-exceptions"></a>
### 13.2 时效性内容与链接的边界

S3 对品牌故事明确允许节日、新品等时效性表述，这是一般 A+ 时效性限制的例外；价格和促销限制仍适用。

S2、S6 提供的本品牌 ASIN 与 Brand Store 预设链接属于模块功能。应填写官方模块的 ASIN 或店铺字段；不要将其理解为可以自行在图片或正文放入任意 URL、二维码或站外引流。

<a id="ai-person-disclosure"></a>
### 13.3 写实 AI 人物的元数据要求

S9 要求适用媒体在上传前标记写实 AI 生成人物：在 XMP 的 dc:subject 字段加入 contains-synthetic-performer。A+ 资产上传界面若提供相应 AI 人物选项，应按界面要求填写并确认标记。

该特定标记适用于完全由 AI 生成的写实人物。没有人物、非写实人物或仅用 AI 修饰真实人物，不需要这个特定标记。不要从这一点推导出其他素材权利或内容要求被豁免。

<a id="publishing-checklist"></a>
## 15. 制作、提交与排查流程

1. **确认目标站点、品牌与产品范围。** 核对语言、账户角色、品牌 ASIN，确认本套内容适合每个应用商品。
2. **选择模块。** 区分贯穿背景、焦点图片、原生 Q&A、Logo 与系列展示；根据实际后台记录像素和字符要求。
3. **完成内容检查。** 先锁定用户提供或确认的原稿及修改授权，核对成品逐字一致；按[第 5.1 节](#copy-integrity)检查原词和相近词形。看正文、图片小字、Logo、图标、alt-text 和链接字段；将事实证据、政策许可及设计建议分别记录。
4. **检查图片。** 使用清晰源稿、RGB、合规格式和文件体积；独立安排移动端背景，预览裁切、遮挡与文字可读性。
5. **应用 ASIN 并提交。** 核对变体范围和 Applied ASINs 状态；保存内容名称、语言、应用列表和提交日期。
6. **核验审核与前台。** S4 提示审核可能最多七个工作日，通过后发布可能还需二十四小时；这是官方排查参考，不是每个项目的保证时限。
7. **获批仍缺失时排查。** 检查应用 ASIN、语言和发布等待时间；仍未解决再开支持工单。拒审则按明确原因修改后重新提交。

建议支持工单提供：内容类型 Brand Story、项目名称或 ID、站点、语言、具体缺失 ASIN、审批与提交时间、Applied ASINs 状态、前台位置截图、已有 case ID。截图及记录含账户信息时，只向处理该问题的授权支持渠道提交。

**检索时的简短答案：** 桌面背景常见 1464 × 625 px，移动背景常见 463 × 625 px，均须核对当前后台；焦点图 362 × 453 px；单张小于 2 MB；100～500 KB 与 300 KB～1 MB 是压缩建议；品牌故事支持 Q&A 原生卡片，也可考虑问答图片排版，但不保证审核通过；竞品实例不等于平台许可。
