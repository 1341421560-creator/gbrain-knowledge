## 取用入口与店铺边界

[机器可读版式目录](版式目录.json)按“店铺→版式变体→规格→当前修订”选取。未明确店铺时先确认；缺规格就标缺，不借moment配置，不把其他规格直接缩放后当作已确认版本。

| 版式 | 当前视觉修订与用途 | 教程证据状态 |
| --- | --- | --- |
| [J01](#j01) 单型号四宫格 | 对应操作位置清晰浮层；一格兼容、三格对比 | 对应iOS18菜单结构，原始About型号值为空，成图型号为示例；不默认作完整真实教程 |
| [J02](#j02) 合并型号单机身 | 一个代表手机配多个兼容型号，绿色区加四张红卡 | 旧iPhone11／iOS15.1共用菜单与目标示例，非12／12Pro或14／13的完整实机证据 |
| [J03](#j03) 合并型号多机身 | 按外观分组展示多台代表手机 | SVG绘制示意，硬件修正版可复现，不是真实系统截图 |

三种版式均保留高级A+1464×600、普通A+970×600、移动端600×450。当前指针只确定视觉参考；新真实教程必须再通过[设置页面覆盖索引](../../通用素材/设置页面/覆盖索引.json)的机型、系统、有效结果和完整步骤检查。

## J01：单型号四宫格

当前修订为`原生iOS浮层_20261103`，已确认iPhone13 Pro、13 mini、13 Pro Max、14 Pro Max、14 Pro、14 Plus共6款×3规格的浮层排版。

[高级参考](参考结果/20261103_统一浮层版/iPhone14Pro_高级A加_1464x600_统一浮层版.jpg) · [普通参考](参考结果/20261103_统一浮层版/iPhone14Pro_普通A加_970x600_统一浮层版.jpg) · [移动参考](参考结果/20261103_统一浮层版/iPhone14Pro_移动端_600x450_统一浮层版.jpg) · [用户确认的浮层参考](参考结果/20261103_统一浮层版/用户确认_iPhone11ProMax_浮层排版参考.png)

Settings、General、About、Model Name四个清晰浮层放在对应操作位置，第四台另保留绿色型号提示；取消手机底部另排步骤标签和引线。高级版横排四台完整手机，普通版为2×2自然裁切，移动版为四条纵向教程。沿用本店海军蓝、红绿兼容提示和for前缀，不套moment蓝框或底部胶囊排。

[四宫格位置](工程/原生iOS浮层_20261103/配置/四宫格版式.json) · [浮层尺寸与字号](工程/原生iOS浮层_20261103/配置/浮层参数.json) · [教程裁切与虚化](工程/原生iOS浮层_20261103/配置/教程参数.json) · [界面处理](工程/原生iOS浮层_20261103/配置/界面处理.json) · [样式](工程/原生iOS浮层_20261103/配置/样式.json)

来源为对应机型Vodafone iOS18菜单及机框。原始About型号值留空，浮层型号是示例注释，不能称原始结果或未经编辑的连续实录。既有18张哈希复现一致只证明复现，背景截图禁词也未因此全部通过；新真实教程需换用有效原始结果。

复现现有视觉参考时，在`工程/原生iOS浮层_20261103`运行，省略目标参数会生成六款三规格：

```powershell
bun ./脚本/生成JPG.mjs <Sharp模块路径> <项目输出目录> [iPhone14Pro]
```

<a id="j02"></a>
## J02：合并型号单机身

当前修订为`真实iOS_20261029_v3`，保存12／12Pro、14／13两组；一台组内代表手机配完整兼容名单，不因用一个代表就扩大兼容范围或宣称组内系统相同。

[高级参考](参考结果/真实iOS合并单机身/iPhone12及12Pro_高级A加_1464x600_重点虚化v3.jpg) · [普通参考](参考结果/真实iOS合并单机身/iPhone12及12Pro_普通A加_970x600_重点虚化v3.jpg) · [移动参考](参考结果/真实iOS合并单机身/iPhone12及12Pro_移动端_600x450_重点虚化v3.jpg)

绿色兼容区加四张红色对比卡；合并名称完整分行，屏幕只展示一个代表机。三端配置分别在[高级](工程/真实iOS机型卡片_v3/配置/合并_高级A加.json)、[普通](工程/真实iOS机型卡片_v3/配置/合并_普通A加.json)、[移动](工程/真实iOS机型卡片_v3/配置/合并_移动端.json)，样式与机身标尺由该工程配置控制。

当前菜单底图共用iPhone11／iOS15.1，目标名称是示例，既有图属于原图底图加示例标注，不默认用于新真实教程。旧e／Pro独立工程和旧参考不再成为当前入口。

在`工程/真实iOS机型卡片_v3`复现现有参考：

```powershell
node ./脚本/生成JPG.mjs <Sharp模块路径> <项目输出目录> iPhone12及12Pro
node ./脚本/生成JPG.mjs <Sharp模块路径> <项目输出目录> iPhone14及13
```

这个工程同时被J01直接导入机型卡片模块，不能因名称含v3而整删。其读取器仍遍历旧物理资料及全部iOS devices/assets，保留运行依赖不代表这些原图都适合作为新教程默认素材。

<a id="j03"></a>
## J03：合并型号多机身

当前修订为`SVG示意_硬件修正_20261029_v3`，用于M02–M09八组。高级版是上方多机身绿色区、下方两张红卡、右边四台完整教程；普通与移动版下方四张红卡，教程分别为2×2裁切和纵向条带。

[高级参考](参考结果/多机身合并_示意教程/M02_iPhone6_6s_7_8_SE2020_SE2022_v3_真实机型教程_高级A加_1464x600.png) · [普通参考](参考结果/多机身合并_示意教程/M02_iPhone6_6s_7_8_SE2020_SE2022_v3_真实机型教程_普通A加_970x600.png) · [移动参考](参考结果/多机身合并_示意教程/M02_iPhone6_6s_7_8_SE2020_SE2022_v3_真实机型教程_移动端_600x450.png)

[版式](工程/多机身合并_SVG示意_20261029/配置/版式.json) · [样式](工程/多机身合并_SVG示意_20261029/配置/样式.json) · [组别与对比](工程/多机身合并_SVG示意_20261029/配置/制作清单.json) · [教程硬件与字段](工程/多机身合并_SVG示意_20261029/配置/教程规格.json)

M02、M03代表机为6s、6s Plus的Home键结构；其他组分别按真实宽刘海或小刘海。绘制示意不是原始截图，不能把6s的系统推广到6，也不能因为历史文件名含“真实机型教程”就升级证据状态。只有任务明确接受示意范围时才按该方式制作。

在`工程/多机身合并_SVG示意_20261029`复现已有SVG示意，省略group会生成八组三端：

```powershell
node ./脚本/生成整套.mjs --sharp-module <Sharp模块路径> --output <项目输出目录> --group M02
```
