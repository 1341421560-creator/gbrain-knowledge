# 型号选择A+真实设置页面：选材与字段核对

> 真实设置页是跨店铺通用素材，统一从[设置页面覆盖索引](覆盖索引.json)选择。必须分别核对实际机型、系统版本、入口、菜单和非空型号结果；未知系统或留空结果保留素材价值，但不能默认用于新的完整真实教程。

<a id="selection"></a>
## 按机型与系统选择原始页面

先确定兼容清单及组内教程代表机，再按覆盖索引的model_id、os.name和os.version选材。同一机型的不同系统分别取证；同品牌、相似界面、网页标题、文件名或上传日期都不能代替原图与版本证据。

只有model_verified、os_verified、result_verified、sequence_complete全部为true，且default_usable_for_new_tutorial=true的序列进入默认选择。系统证据可能来自画面可见版本或来源页面明确标注，索引分别记录证据等级；没有证据保持未知，不能猜版本。任务指定语言、地区或运营商时还须匹配相应来源；网站所在国不等于实机地区已确认。

一款手机壳兼容多款机型时可以只做一套组内代表机教程，外部兼容范围与屏幕实际代表机分别记录。兼容多机型不代表这些手机支持相同系统，换机框或改结果文字也不能取得另一机型的真实页面。

<a id="fields"></a>
## 实际入口与型号字段

| 平台 | 真实操作与字段核对 |
| --- | --- |
| iPhone | 按该机型与系统的原图进入Settings → General → About，读取实际存在的Model Name。Name是可修改设备名，只显示iPhone不能识别6、7、8或SE。 |
| 旧iOS | 有些版本实际使用Model／Model Number。必须保留真实编号读取方式和准确映射；没有Model Name就不伪造一行，来源型号值留空也不能反推真实手机没有型号信息。 |
| Samsung Galaxy | 先进入Settings，再进入About phone读取结果；不套用iOS的General，也不制造还需点击的“型号”子菜单。 |
| 三星字段差异 | 已核实S23／Android13的Product name为Galaxy S23，Model name为SM-S911B/DS，上方可编辑设备名称不是唯一型号依据。其他机型和系统仍逐图核对，不能把Galaxy名称填进实际显示SM代码的字段。 |

首屏必须有实际设置入口，中间步骤与原菜单一致，末屏必须能够完成真实型号识别。结果被遮挡、滚出画面、留空，或只有可编辑昵称时，都只能算部分资料。

<a id="source-classes"></a>
## 原始、发布处理与历史示意分开

| 类别 | 保存与使用要求 |
| --- | --- |
| 真实原始 | 完整保留原始字节、URL、来源机型／系统、视频时间点、原始字段和SHA-256。原稿可以含Logo、昵称、识别信息或无关文字，不能因此称可直接发布。 |
| 发布处理 | 从真实原图派生的裁切、放大、遮挡或虚化版本，明确关联原图并记录范围。只能处理无关区域，不能更改实际型号、系统、菜单和识别字段；放大框只是操作注释。 |
| 历史示意 | 绘制页面、跨机型改值和未核实的旧混合来源组合，只保留其真实用途和来源边界，不作为新教程默认真实覆盖。 |

旧devices里跨型号共用iPhone11菜单的绑定不会因目标键名而变成真实覆盖；来源About留空后另加目标型号也仍是示例。原始图片、派生图片与示例的状态分开，不用一个“已核验”笼统代替。

<a id="store-boundary"></a>
## 硬件、店铺与成品验收边界

真实机框应与代表机硬件一致，保持Home键、刘海、灵动岛或打孔的实际结构和自然比例；不使用任意黑色矩形制造刘海。机框按同型号实体形状复用，来源页面标注的系统不限制该实体轮廓；主屏、菜单与结果的系统仍须匹配。

放大框尺寸、位置、配色、虚化、排列和发布遮挡属于店铺模板。moment与JHWVVTF分别读取自己的当前模板，不把任何店铺的参数写成通用截图默认。

导出后将原始页面与最终图对照，检查入口→菜单→结果能否真实操作，目标是否完整，屏幕与型号是否匹配，以及发布画面无不应出现的品牌Logo和识别信息。再按任务站点词库检查所有可辨认文字；OCR漏识别、字小、已虚化或哈希复现都不能代替真实性与发布验收。

完整制作与交付检查见[制作与验收](../../通用流程/制作与验收.md)。原始图片继续按iOS／Android及来源目录保存，来源与状态统一在覆盖索引维护；换机型、系统或来源时重新核对，不复制整套来源索引。
